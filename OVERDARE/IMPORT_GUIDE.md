# Kremlin Palace → OVERDARE 임포트 가이드

출처 블렌드: `Kremlin_Grand_Palace_COMPLETE.blend` (저장됨, 67.1 MB)
산출 폴더: `Kremlin_Palace_Phase3\OVERDARE\`

**임포트는 사용자가 직접 한다.** 나는 파일만 준비하고, 끝난 뒤 `UGCLocalAssetTable.json` / `.ovdrjm`을 CLI로 읽어 검증한다. Studio의 Bulk Import UI는 조작하지 않는다.

## 1. 재질 → 팔레트 아틀라스 1장

**임포트 단위는 파일도 오브젝트도 아니고 MATERIAL이다.** 재질 수가 곧 퍼블리시되는 에셋 수이고, 그게 Studio 재시작 횟수를 결정한다.

이 맵의 재질 22개 중 20개가 단색/절차적이라 **512×512 팔레트 한 장(24슬롯, 5.6 KB)**에 전부 담았다. 각 면의 UV를 해당 슬롯 중심 한 점으로 보내는 방식이라 베이크가 필요 없다 — 순수 UV 산술이다.

결과 재질 3개:

| 재질 | 텍스처 | 크기 |
|---|---|---|
| `KRM_PALETTE` | `KRM_palette.png` 512² | 5.6 KB |
| `KRM_ARMCHAIR` | `KRM_armchair_C.png` 1024² | 2.1 MB |
| `KRM_KNIGHT` | `KRM_knight_C.png` 1024² | 1.7 MB |

원본 2048²를 1024²로 줄였다(공식 권장 512, 실측 캡 1024). 다운스케일은 **Blender 밖에서** 했다 — Blender 번들 Python에는 PIL이 없고 `img.scale()`은 헤드리스에서 널 버퍼를 건드린다.

## 2. 좌표 규약

- **STATIC은 월드 좌표 그대로** 내보냈다. 임포터가 모든 파일을 (0,0,0)에 떨어뜨리면 맵이 스스로 조립된다. 파일별 오프셋 표가 필요 없다.
- **마스터는 로컬 좌표**로 XY 중심·Z 바닥 기준 재중심. 배치는 `placements.csv`.
- 배치 변환: `X = x*100`, `Y = z*100`, `Z = y*100`, `yaw_deg = -degrees(rot_z)` (Blender m Z-up → OVERDARE cm Y-up)
- FBX 익스포트는 `axis_up='Y', axis_forward='-Z'`

⚠️ **yaw 부호는 엔진 밖에서 검증 불가.** 임포트 후 비대칭 오브젝트 하나(기사상 등)로 확인할 것.

⚠️ **`UnitExtent`는 half-extent다.** 소스와 비교할 때 2배 해야 한다. 안 그러면 정상 임포트가 50% 축소된 것처럼 보인다.

## 3. 하드 제한 (공식 + 실측)

| 항목 | 제한 |
|---|---|
| 메시당 삼각형 | ≤ 30,000 — **이 딜리버리는 파일당·메시당 둘 다 ≤28,000** |
| 파일 크기 | ≤ 250 MB |
| 텍스처 | ≤ 15 MB, 권장 512² (실측 캡 1024²) |
| 포맷 | `.fbx` / `.obj` 만 |

과거에 스펙이 "파일당 30k"와 "메시당 30k"로 서로 달랐다. **둘 다 만족**시키는 게 안전하다.

## 4. 파일당 메시 1개 — 반드시

임포터는 **오브젝트마다 월드 에셋을 하나씩 퍼블리시하고 그때마다 transient world를 누수**시킨다. 오브젝트가 많은 파일은 퍼블리시 수를 폭발시키고, 심하면 Studio가 죽는다(`Cannot generate unique name for 'MetaBaseWorldSettings'`).

그래서 이 딜리버리는 **모든 파일이 메시 1개**다. 버킷에 담긴 오브젝트들을 bmesh로 하나로 합쳐서 내보낸다.

## 5. 충돌체는 FBX에 넣지 않는다

**OVERDARE는 Unreal의 UCX 규약을 구현하지 않았다.** 둘 다 죽은 길이다:
- 단독 `UCX_*.fbx` → "Failed to create asset"
- 렌더 파일 안의 `UCX_` 메시 → Studio 크래시

대신 **엔진 `Part`**를 쓴다. 박스는 Part 그 자체라 1:1이고, 네이티브 프리미티브라 **퍼블리시 에셋을 0개** 소비한다. 설정: `Transparency 1`, `CanCollide true`, `Anchored`, `Static`.

→ 충돌 Part 목록은 이 딜리버리에 아직 **없다**. 벽·바닥·계단 기준으로 별도 생성이 필요하다 (`overdare_create_instances`용 JSON).

## 6. 임포트 배치 규칙 (실측 OOM 기준)

**배치당**: 압축 해제 기준 텍스처 ≤400 MB (699 MB에서 OOM 확인), 파일 ≤10개, 유닛 ≤20
**세션당**: 유닛 ≤40, ≤500 MB — **세션 사이에 Studio 재시작** (누수는 재시작에만 리셋된다)

이 맵은 재질이 3개뿐이라 유닛 압박이 거의 없다. 텍스처 총량도 3.8 MB라 배치 제한에 걸리지 않는다.

## 7. 임포트 후 검증

1. `UGCLocalAssetTable.json`(UTF-16)에서 파일마다 **`STATIC_MESH` + `MODEL`** 두 에셋이 등록됐는지 확인
2. **MeshPart의 `MeshId`는 반드시 `STATIC_MESH` id** — `MODEL` id는 에디터에선 보이지만 **플레이 중엔 안 보인다**
3. 좌표로 검증한다. 스크린샷 말고 CLI/데이터로 (이 Studio 빌드는 캡처·카메라 조준이 깨져 있다)
4. `UnitExtent × 2`로 소스 치수와 대조
5. yaw 부호를 비대칭 오브젝트 하나로 확인

| 인스턴스 마스터 | 53 / 68,107 tris |
| 배치 행 (`placements.csv`) | 1,311 |
| 재임포트 총 삼각형 | 2,161,015 (매니페스트와 전부 일치) |

| 공식 한계 위반 | **0** |

단일 오브젝트가 캡을 넘던 9건은 최장축 공간 분할로 21청크가 됐다 (로제트 73,936 / 패널 스크롤 76,896 / 갤러리 스크롤 74,048 등). **데시메이트는 쓰지 않았다** — 장식을 부순다.

배치 좌표는 표본 12개에서 **오차 0 m**로 역산 검증했다.

### 정점 경고

OVERDARE는 **삼각형이 아니라 정점을 센다.** 권장치는 프롭당 ~700정점 / 화면당 ~70,000정점인데, 이 맵은 총 119만 정점이다. 거부 사유는 아니지만(권장치일 뿐) 한 화면에 홀 전체가 들어오면 권장치를 크게 넘는다. 실기기에서 프레임을 보고 필요하면 원거리 장식부터 빼야 한다.

## 9. 임포트 순서

파일당 3유닛(MODEL + STATIC_MESH + TEXTURE) 기준 **총 429유닛**.
세션당 40유닛·배치당 10파일 규칙을 적용하면 **11세션 / 세션당 13파일 / 2배치**다.

전체 표는 `import_plan.json` (세션·배치·파일·tris·MB). 세션 앞 5개:

| 세션 | 파일 | 배치 | 유닛 | tris | MB |
|---|---|---|---|---|---|
| 1 | 13 | 2 | 39 | 476 | 0.3 |
| 2 | 13 | 2 | 39 | 49,527 | 6.8 |
| 3 | 13 | 2 | 39 | 4,316 | 0.4 |
